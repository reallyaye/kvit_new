# Руководство по участию в разработке (Contributing Guide)

Мы приветствуем ваш вклад в развитие проекта **Kvit-App**! Пожалуйста, ознакомьтесь с правилами разработки, кодстайла и процесса отправки изменений.

---

## 🛠️ Настройка локального окружения

1. **Клонирование репозитория**:
   ```bash
   git clone https://github.com/reallyaye/kvit_new.git
   cd kvit_new
   ```

2. **Создание и активация виртуального окружения**:
   ```bash
   python -m venv venv
   # Linux/macOS:
   source venv/bin/activate
   # Windows:
   .\venv\Scripts\activate
   ```

3. **Установка зависимостей**:
   ```bash
   pip install -r requirements.txt
   pip install ruff bandit pytest
   ```

4. **Настройка файла окружения**:
   ```bash
   cp .env.example .env
   ```
   *Сгенерируйте и укажите `GRPC_API_KEY` и `ADMIN_PASSWORD_HASH` согласно подсказкам в `.env.example`.*

---

## 🧪 Запуск тестов и проверок качества

Перед отправкой любого Pull Request или коммита обязательно убедитесь, что все тесты и проверки проходят успешно:

1. **Запуск тестового набора (Unit + Security + Fuzzing)**:
   ```bash
   python run_tests.py
   ```

2. **Линтинг кода (Ruff)**:
   ```bash
   ruff check .
   ```

3. **Статический анализ безопасности (Bandit)**:
   ```bash
   bandit -r . -x ./tests,./tmp,./scratch -ll -ii
   ```

4. **Стресс-тестирование базы данных (опционально при изменении схемы/индексов)**:
   ```bash
   python benchmarks/load_test_sqlite.py
   ```

---

## 📝 Правила оформления коммитов и PR

* **Язык коммитов**: Сообщения коммитов должны быть написаны на русском языке с понятным префиксом:
  * `feat: ...` — новая функциональность
  * `fix: ...` — исправление ошибки
  * `безопасность: ...` — усиление защиты или исправление уязвимости
  * `ci: ...` — изменения в пайплайнах GitHub Actions
  * `docs: ...` — обновление документации
  * `тесты: ...` — добавление или обновление тестов / бенчмарков
* **Безопасность**: Никогда не коммитьте `.env`, боевые сертификаты, персональные данные абонентов и файлы SQLite баз данных.
